# 모든 장면에 적용하는 분석 절차 v1.0.0

이 분석의 질문은 “흐린 사진 한 장을 더했을 때 그 사진을 뺀 경우보다 나머지 공간 복원이 나빠지는가?”다. 승인된 `EXPERIMENT_PLAN.md` 10·11·14·15절을 구현한다. office를 먼저 분석하며, 이후 장면도 같은 코드·효과 문턱·분모·표·그림을 사용한다.

## 실행 명령과 저장 위치

```sh
.venv/bin/python experiments/run_all.py analyze --scene office
.venv/bin/python experiments/run_all.py analyze --scene courtyard
# 전체 주 분석 대상 중 현재 결과가 있는 장면들을 다시 분석하고 미계산 장면을 표시
.venv/bin/python experiments/run_all.py analyze
# 서버에서도 같은 인터페이스
.venv/bin/python experiments/run_all.py analyze --target cuda-server
```

`local`이 기본값이다. `--results-root`는 선택한 실행 위치의 결과 루트다. 분석기는 CPU에서 저장된 예측을 검산하며 신경망·가중치·GPU 추론을 추가하지 않는다. 공통 진입점은 기존 `run_all.py`를 사용한다. 분석 파일은 기존 추론 소스 잠금에 포함되지 않는 위치에 추가했다.

```text
experiments/

│   ├── core.py                      U·판정·전환·장면 동일 가중 집계
```

상위 공통 보고서와 표는 매번 **이번 요청 장면 집합**으로 만든다. 앞서 만든 다른 장면의 상세 보고서는 보존한다. 전체 통합을 하려면 scene 옵션 없이 실행한다. 통합 시 과거 보고서 숫자를 합치지 않고 원시 결과를 같은 분석 코드로 다시 읽어 분석 버전이 섞이는 것을 막는다.

## 입력 검증과 재채점

입력은 `results/executions/<scene>/`의 `inputs.json`, `batch_status.json`, `cohort_configuration.json`, 모델별 `environment.json`, `runs.jsonl`, `utilities.json`, `predictions/*.npz`다. 또한 입력 manifest가 가리키는 준비 RGB·공식 깊이·마스크·metadata snapshot과 공식 사진 선정 결과가 필요하다. 원본 대형 사진 archive·checkpoint·모델 실행은 분석에 필요하지 않다.

검증은 다음 순서로 수행한다.

1. 승인 프로토콜·계획·연구 잠금, 장면 배정과 실행 환경 지문을 비교한다.
2. 장면·모델·집합 크기·타깃·12각도·다섯 지표의 계획 키를 만든다. 중복·계획 외 키는 오류다. 없는 행은 `missing`으로 보존한다.
3. 사진 집합의 크기·중첩·공식 선정 명단, 공식 GT 파일/마스크의 해시·크기·dtype·픽셀 수와 준비 RGB 해시를 대조한다.
4. 모든 저장 예측 파일을 첫 성공 시도의 SHA-256과 대조한다. 예측의 사진 순서와 DROP의 공통 컨텍스트가 정확해야 한다. 여러 서로 다른 성공 결과 중 하나를 선택하지 않는다.
5. 예측의 저장된 `depth_common_grid`와 `c2w`를 CPU에서 공식 GT로 다시 채점한다. 재계산 E_DROP·E_ADD와 저장 점수는 상대 오차 1e-8·절대 오차 1e-10 이내에서 일치해야 한다. 모델 추론은 재실행하지 않는다.
6. 각 행의 U를 E_DROP−E_ADD로 다시 만들고 저장 `utility_raw`와 대조한다. 모델과 ADD/DROP 사이의 같은 GT 마스크·평가 픽셀 수를 확인한다.
7. 분석이 끝날 때 사용 입력이 바뀌지 않았는지 확인한다. 실행 중 파일이 바뀌는 자료는 멈춘 결과 또는 별도 고정 snapshot에서 분석한다.

파일 손상·해시·점수 불일치와 정상적인 “아직 미계산”을 구분한다. 전자는 분석 실패로 처리한다. 후자는 전체 계획 분모를 보존하고 결과가 없는 장면/행을 명시한다. `complete`라 기록됐는데 예측·지표가 빠져 있으면 완료 상태를 그대로 믿지 않는다.

분석은 임시 디렉토리에서 만들어진다. 같은 결과 루트에서 분석 두 개가 동시에 보고서를 교체하지 않도록 파일 잠금을 사용한다. 모든 검증을 통과한 뒤에만 기존 `results/analysis/`를 교체한다. 오류가 나면 기존 정상 보고서를 보존하고 `results/analysis_failure.json`에 이유를 쓴다. 실행 결과 폴더는 읽기 전용 입력으로 취급한다.

## U와 네 가지 판정

모든 지표에서 `U = E_DROP − E_ADD`다. 양수는 타깃 추가로 오차가 감소, 음수는 증가했다는 뜻이다. 포즈의 저장 `utility` 열은 상대 변화율이어서 주 분석에 사용하지 않는다.

주 지표는 깊이 AbsRel이다. 주 효과 문턱은 ε=0.0005이고, 경계를 포함한 −ε≤U≤+ε는 문턱 이내다. 도움은 U>+ε, 해로움은 U<−ε, 필요한 오차가 없는 경우는 평가 불가다. AbsRel과 U에 100을 곱해 표시할 때 각각 % 오차와 percentage point라는 서로 다른 단위를 쓴다. 원시 부호와 ε=0·0.0001·0.0005·0.001의 민감도도 모두 보존한다. 보조 지표는 원래 단위와 원시 부호를 사용한다.

각 각도에서 기본 분모는 계획 타깃 수 m이다. 평가 불가를 제외한 유해율은 보조 열이다. 평균·중앙값·Q25·Q75·최솟값·최댓값은 유효한 타깃 관측값의 기술 분포이고 신뢰구간이 아니다. 한 컨텍스트의 12각도에서 DROP 기준과 픽셀 가중치는 고정돼야 한다.

그래프 x축은 관측 단계를 같은 간격으로 나열하고, 모든 패널에 실제 yaw span 숫자(0, 0.025, 0.05, …, 4도)를 표시한다. 각도 증가폭은 일정하지 않으며 표시 간격이 실제 각도 차이에 비례한다는 뜻은 아니다.

## 전환과 역전환

주 전환의 자격은 clean부터 U>+ε인 곡선이다. 이후 처음 U<−ε가 관측되면 그 음수 앞의 **마지막 도움 관측값**과 첫 해로움 관측값 사이를 구간으로 기록한다. 바로 앞 단계가 문턱 이내라고 해서 그 단계를 양수 경계로 사용하지 않는다.

중간의 문턱 이내·평가 불가 단계는 버리지 않고 구간 안의 목록으로 남긴다. 모든 양수→음수·음수→양수 사건과 첫 해로움 뒤의 회복을 기록한다. clean부터 유해·문턱 이내·평가 불가인 곡선을 clean 도움→유해 전환의 분자에 넣지 않는다.

12단계가 전부 유효한 완전 곡선의 전환을 주 요약으로 쓰고, 불완전 곡선에서 실제 관측한 전환은 별도 열이다. 분모는 여전히 전체 계획 곡선 m이며, 자격 있는 clean 도움 완전 곡선만을 분모로 한 값은 보조로 제공한다. 선형 보간·단조성·보편적 임계각을 가정하지 않는다.

## 여러 장면·장치의 결합

모델·크기·각도·지표별로 각 장면의 계획 분모 비율을 먼저 구한 뒤 장면을 같은 가중치로 평균한다. 장면 간 중앙값·최소·최대와 실제 사용 장면 수도 쓴다. 같은 타깃을 모두 합친 값은 `pooled_targets_secondary`로 표시한다. 미계산 장면을 0으로 대입하지 않는다. 사용/요청 장면 수와 전체 10장면 진행 상태를 함께 공개한다.

전체, 장치별, 실행 그룹별 집계가 같은 표 구조를 쓴다. MPS/CUDA의 결론상 동등성은 연구의 가정이며 장치별 표로 장치 효과를 추정하지 않는다. 하나의 장면 안에서 모델·ADD/DROP 플랫폼이 일치해야 한다.

모델 쌍의 보조 비교는 같은 장면·타깃·컨텍스트·각도·지표에서 양쪽 모두 유효한 경우에만 만든다. 제외 수와 실제 DROP/ADD 오차를 공개한다. U가 크다는 이유로 절대 정확도가 더 높다고 해석하지 않는다.

## 진단·탐색·사례

공식 고정 마스크에서 유한한 0·음수와 NaN/Inf의 수·비율을 예측으로부터 계산한다. 주 채점은 유한한 비양수도 오차로 포함하고 비유한은 실패로 남긴다. 비양수 하나도 허용하지 않는 엄격 점수는 진단만 한다. 재사용된 DROP/clean 픽셀을 여러 비교에서 세는 수와 독립 추론 횟수를 구분한다.

대표 타깃은 각 집합의 사진 ID 사전순 첫 번째·가운데·마지막이다. 결과를 보고 사례를 고르지 않는다. GT 선정에서 이미 저장한 사진 쌍 겹침과, 고정 GT에서 분석 중 파생한 기준선·회전·깊이 분포를 탐색 표·산점도로 제시한다. 파생 시점을 숨기지 않고 원인·유의성·확증 분석으로 표현하지 않는다.

단일 seed의 기술 통계이며 p-value·신뢰구간·재실행 안정성을 만들지 않는다. 5·10·15장 차이는 사진 수와 함께 구성이 달라지는 비교이고, 한 장면 결과를 모든 환경의 공통 임계각·전체 3D 완전성·실제 프레임 삭제 정책 개선의 증거로 확대하지 않는다.

## 이후 변경의 추적

분석 버전은 `analysis/core.py`의 VERSION과 모든 분석 코드 SHA-256으로 식별한다. 보고서마다 분석 정의·실제 코드·라이브러리 버전·전체 입력·출력 해시를 보존한다. 분석 규칙을 바꾸거나 버그를 고친 경우 원시 결과에서 관련 장면 전체를 같은 버전으로 다시 분석한다. 완료된 모델 예측·점수·추론 잠금을 바꿔 분석 기준에 맞추지 않는다.
